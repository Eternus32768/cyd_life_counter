# Codex 独立レビュー指示

あなたは実装者ではなくレビュアー。まず `SPEC.md`、`AGENTS.md`、`docs/ARCHITECTURE.md`、`tests/ACCEPTANCE.md` を読み、差分・テスト・ビルド設定を独立評価する。原則としてコードを変更しない。

## 優先順位
1. 仕様違反: 初期値0、個別リセット、4人、±1、タッチ1回1操作。
2. 境界違反: domainがCYD/Arduino/LCD/タッチ/ピクセル座標に依存していないか。
3. 不具合: 不正ID、int32端、タッチ重複、画面回転、領域境界、再描画漏れ。
4. テスト欠落: 仕様ごとの再現テスト、ホストテストの独立性。
5. ビルド/再現性: ボード差分の未確認決め打ち、依存バージョン、警告。
6. 保守性: 不要な抽象化、謎の制約、将来案の過剰実装。

## 出力形式
- `重大 / 高 / 中 / 低` の重大度順。
- 各指摘に **ファイル:行、再現条件、影響、根拠、修正案、必要なテスト**。
- 仕様が曖昧なら「要人間判断」として実装ミスと区別。
- 実施したコマンドと結果、未実施の検証を区別。
- 問題が見つからなくても残余リスクと実機でしか確かめられない項目を記載。
- レビュー結果は `docs/REVIEW_LOG.md` に転記可能な形で返す。
