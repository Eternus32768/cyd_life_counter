# 実機の向き・色・タッチを確定させる手順

目視の報告だけで表示の向きやタッチ対応を詰めると、解釈の食い違いで手戻りが起きる。
`cyd_probe.ino` は**判定を人の解釈に依存させない**ための診断スケッチ。2026-10-11 の実機確認で有効だった。

## なぜ必要か（この手順がなかったときに起きたこと）
- 「上下が逆」「左右が逆」という報告が、基板を持つ向きによって変わり、同じビルドで相反する報告が出た。
- 「赤が青っぽい」が、色順（rgb_order）の問題ではなく反転（invert）の副作用だった。純色を見ないと切り分けられない。
- タッチ座標の実測値を、そのときの実効回転と対応付けずに記録したため、必要な補正を取り違えた。

## 使い方
```powershell
# ビルドと書き込み（BOOTボタンを押したまま実行する。docs/HARDWARE.md 参照）
& $cli compile --fqbn esp32:esp32:esp32 --build-path <tmp> <このフォルダ>
& $cli upload  --fqbn 'esp32:esp32:esp32:UploadSpeed=230400' --input-dir <tmp> -p COM4 <このフォルダ>
```
書き込み後は RST か USB 抜き差しで起動する（この個体は書き込み後もダウンロードモードに留まる）。

シリアル(115200)コマンド: `0`〜`7` = 回転変更、`i` = invert 切替、`c` = 再描画。
**回転は焼き直さずに切り替えられる**ので、BOOTボタンを押す回数を減らせる。

## 判定の原則
1. **向きの基準を物理的な目印で固定する。** 「上下」ではなく「USBコネクタが右のとき」と書く。
   基板を180°持ち替えると同じビルドでも報告が逆になる。
2. **非対称なものを描く。** 四隅ラベル(TL/TR/BL/BR)と非対称文字(F)で、回転と鏡像を一意に判定できる。
   対称な図形や `0` では判定できない（180°回転しても同じに見える）。
3. **純色に文字ラベルを添える。** `RED`/`GREEN`/`BLUE` の帯が何色に見えるかで、
   チャンネル入れ替えと反転を切り分けられる。混色の見た目からは逆算できない。
4. **タッチは数値で測る。** 生値と変換後座標をシリアルへ出し、変換後座標に印を描く。
   「ずれている」という主観ではなく、どの軸がどれだけずれたかが分かる。
5. **測定値には、そのときの実効回転を必ず併記する。** 設定を変えながら測ると、
   どの条件の測定値か分からなくなり、補正の方向を誤る。
6. **1点ずつ測る。** 複数点を順番に触ってもらうと、順番の取り違えで解釈が割れる。
   曖昧さが出たら「USBに最も近い角を1回だけ」のように、1対1で対応が付く測り方に切り替える。

## 測定結果の記録先
`docs/HARDWARE.md`。確定値だけでなく、判定根拠（どのパターンがどう見えたか）も残す。
