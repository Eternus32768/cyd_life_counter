## 平置き4人運用の決定（2026-10-11、人間の指示）
- 使用形態: 本体をテーブルに平置きし、4人が周囲に座る。上行(P1/P2)は対面側。
- 決定内容: P1/P2 の文字を180°回転し、`+` / `−` を入れ替える（SPEC.md 更新済み）。
- 影響: `ui::Orientation` を追加し、`QuadLayout::orientation_of()` が領域ごとの向きを返す。
  位置（どちらの半分が `+` か）は UI 層でテスト可能に、文字の回転は実機層（描画）に閉じ込めた。
- 実機層の実装: LovyanGFX v1 に文字単体の回転描画がないため、画面回転を180°違い（回転3）へ
  一時的に切り替え、文字矩形を画面中心で反射した位置に描いて元に戻す。
- 付随して判明した表示上の問題（いずれも実機で確認・修正済み）:
  1. 中央寄せの端数を全領域で同じ向きに丸めると、上下の行が1ピクセル非対称になる。
     → 縦の端数はプレイヤー自身の上側へ寄せる。
  2. 内蔵フォントのセル(6×8)と実インク(5×7)の差（右と下の余白）が回転で反対側へ移り、
     同じ列の数値がフォント1ドット分ずれる。→ セルではなくインク矩形を基準に中央寄せする。
     横の端数は全プレイヤーで同じ向きに丸める（領域が同一座標のため、反転させると一直線に並ばない）。
- テスト: `tests/host/test_layout.cpp` に向きと `±` 入れ替えの検査、
  `tests/host/test_text_layout.cpp` に上下対称・同一列の横位置一致・セル余白の収まりを追加。

## リセットの誤操作防止（2026-10-11、人間の指示）
- 決定: ダブルタップで確定。猶予 **1000ms**（実機で 500ms は短すぎ、1000ms で適切と確認・確定）。
  1回目は待機表示（`R` を黄色）にする。境界はちょうど 1000ms で不成立（`>=` で猶予切れ）。
  時刻はチャタリング除去後の確定時点で計る。
- 不採用: 長押し（必要時間が画面から読み取れず分かりにくい）、確認ダイアログ（初版の範囲外）。
- 待機中に何も表示しないと故障に見えるため、受け付けたことを必ず色で示す。
- 影響: `ui::ResetConfirmation` を追加し、`CounterScreen` がコマンド適用前に通す。
  `+` / `−` は従来どおり即時。待機中に他の操作が入ると解除する。
- テスト: `tests/host/test_reset_confirmation.cpp`（11件）と `test_counter_screen.cpp` の操作シナリオ。
  猶予ちょうどは不成立、別プレイヤーでは成立しない、タイムスタンプ折り返しも検査する。

## 初版UIの暫定配置（2026-10-11、実機操作性で見直す）
※ この節は実機確認前の暫定判断の記録。`+`/`−` の向きは後述の平置き対応で変更済み。
- ~~`+` は各領域の画面外側に沿う帯の上半分、`−` は下半分。全領域で上が `+`~~
  → 平置き対応により、上行は画面上の下半分が `+`（各プレイヤー視点で上が `+`）。
- 帯の幅は領域幅の35%（320×240 で56px）。残りを数値表示に充てる。
- 各領域の画面外周側（上行は上端、下行は下端）に高さ31pxの帯を置き、**画面外側にプレイヤーラベル、
  画面中央側にリセット（36×31px）**を並べる。数値は帯を除いた残り全部（104×89px）を使う。
  理由: 数値とリセットを重ねないため（Codex指摘 R01）。増減操作は左右端で行うので、
  上下端中央寄りのリセットは指の軌道から遠い。隣プレイヤーのリセットとは4pxの間隔を空ける。
  長押し・確認ダイアログは入れていない。
  代替案: 長押し確定、二度押し、中央の共有リセット、数値領域を削ってリセットを大きく取る。
  実機で誤操作や視認性の問題が出れば切り替える。**要人間判断**。
- タッチ確定はデバウンス方式。押下が25ms継続した時点の座標で1回だけコマンド発行し、
  50ms以上離れるまで次を受け付けない。押しっぱなしでの連続加算はしない。
  数値は実機のタッチ応答を見て調整する前提の既定値。
