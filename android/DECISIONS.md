# Android版 決定事項

仕様の正本は `../SPEC.md`。ここには Android 版で CYD 版から変えた点・新規判断だけを書く。

## 前提（2026-11-02、人間の指示）
- 対象はタブレット。平置き4人運用で、P1/P2 の 180° 回転と `+`/`−` の入れ替えを踏襲する。
- 実装は Kotlin。C++ の domain / application / ui を再実装し、ホストテストを JUnit へ移植した（二重管理）。
- 配布は未定。サイドロード以外（公開）は事前承認が必要。

## 構成
- `core/` — 純 Kotlin/JVM。domain・application・ui（レイアウト、ヒットテスト、リセット確認）。Android 依存なし。
- `app/` — （Phase 2 以降）Android アプリ。描画とタッチ入力のみ。
- 環境: JDK 21 / Gradle 9.3.1（wrapper）/ Kotlin 2.2.20 / Android SDK platform 36。`./gradlew :core:test`。

## CYD版との差分
- **リセット待機をプレイヤーごとに独立**（新規判断・要確認）。CYD版は待機が全体で1つで、他人の操作で解除された。
  タブレットは4人が同時に触るため、他人の操作で自分のリセット待機が消えると使えない。
  解除条件: 本人の他操作／猶予切れ(1000ms以上)のみ。猶予・「ちょうど1000msは不成立」は同じ。
- 時刻は単調増加の Long(ms)。32bit折り返し対応は不要なため落とした（テストも削除）。
- 描画抽象 `DisplayRenderer`・`text_metrics`・座標補正は移植しない（OSが描画・座標補正を担う）。
- `LifeEngine.snapshot()` は不変コピー（C++ は const 参照）。

## Phase 2 の実装判断（2026-11-02、実機確認前）
- 描画は Compose を使わず標準 `View` + `Canvas`（依存ゼロ、APK 2.5MB）。`app/` は描画と入力の受け渡しのみで、判定は `core` に任せる。
- タッチ確定: `ACTION_DOWN` / `ACTION_POINTER_DOWN` の指ごとに、その位置で1回だけコマンド発行。離すまで再発火しない
  （CYD の 25ms デバウンスは抵抗膜式向けのため不採用）。マルチタッチは指ごとに独立。**実機で誤タッチを要確認**。
- 横向き固定（`landscape`。`sensorLandscape` だと平置きでセンサー次第で 180° 反転するため不採用）。回転で作り直されないよう `configChanges` を処理。
- 常時点灯（`FLAG_KEEP_SCREEN_ON`）、システムバー非表示（端スワイプで一時表示）。
- minSdk 30（Android 11）。`WindowInsetsController` を直接使うため。ユーザー指定なし、変更可。
- 永続化なし（SPEC どおり）。**アプリがバックグラウンドでOSに終了されると全員0に戻る。** 許容か要確認。
- `Palette` は `core` に置く（色の整数値のみ。CYD と同じ中間調）。

## Codex レビュー反映（2026-11-02、詳細は `docs/REVIEW_LOG.md`）
- AR01: Android 16（targetSdk 36）は幅600dp以上で `screenOrientation` を無視する。アプリレベルの
  `PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY` で一時的に旧挙動へオプトアウト。**targetSdk 37 では無効**。
  その時点で固定方向の代替（または回転に追従しても座席対応を保つ設計）を再検討する。
  **検証（2026-11-02）**: Pixel 9 Pro XL（Android 16）で `wm density 240` により最小幅を672dpに疑似化。宣言なしはアプリ窓が縦長（向き固定が無視）、
  宣言ありは横長（横向きを維持）。実際の600dp以上の端末での確認は未実施。縦向きの端末に入れると、横長の窓が画面上部に小さく表示される
  （レターボックス。平置きのタブレットを横向きで使う運用では全画面になる）。
- AR02: リセット待機の猶予切れ表示は、待機中プレイヤーの最も早い期限に更新を予約する（他人の操作で延びない）。
- `configChanges` を拡張し、設定変更で Activity が作り直されて値が消えないようにした（OSによるプロセス終了での消失は仕様どおり）。
- Gradle ラッパーの配布 SHA-256 を固定。

## 人間の承認（2026-11-02）
- **AJ01**: リセット待機をプレイヤーごとに独立させる判断を承認。`SPEC.md` に Android版の例外として明記。
- **AJ02**: リセットの2回目は、1回目の指が離れてから受け付ける。`TapInput`（core）で実装。
  触れたままの指・二本指の同時接触では確定せず、無視した接触は待機の状態も期限も変えない。他プレイヤーや ± は影響を受けない。
  指の番号は再利用されるため、離れた時点で記録を消す。ACTION_CANCEL・ウィンドウのフォーカス喪失では全て離した扱いにする。
- **AJ02 の範囲（2026-11-02、人間の判断）**: 制約は「1回目の指が触れている間」だけ。別の指がカードやリセット以外に触れていても、
  離して押す通常のダブルタップは成立する（手のひらが乗った状態などの意図的な悪用までは防がない）。「そのカードに他の指が触れている間は
  リセットを受け付けない」案は不採用。

## 実用範囲（2026-11-02、人間の判断）
- 表示が必要な範囲は負号込み3桁（-99〜99）。`-2147483648` など最大11文字の実機表示確認は不要。値は Int のまま、長い値は自動縮小する実装を維持する（範囲を絞る仕様変更はしない）。
- 実機（iPlay 70 mini Ultra, Android 14）で全確認項目が問題なし。内訳は `tests/ACCEPTANCE.md` の「Android版 実機確認」。
